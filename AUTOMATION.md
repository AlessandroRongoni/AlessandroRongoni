# Profile automation

The profile uses a **daily GitHub Actions workflow** (`.github/workflows/sync-research-profile.yml`), also runnable on demand from **Actions → Sync research & GitHub metrics → Run workflow**.

## Research publications

- `scripts/sync_profile.py` looks up publicly indexed works using [OpenAlex](https://openalex.org/) filtered by **ORCID 0009-0002-2907-8998**. It may lag new ORCID entries or index some works differently; it is **not a direct live export of ORCID**.
- To read **directly from ORCID**, register a [Public API client](https://info.orcid.org/documentation/integration-guide/registering-a-public-api-client/) and store `ORCID_CLIENT_ID` and `ORCID_CLIENT_SECRET` as repository Actions secrets. The script requests a read-only `/read-public` token via OAuth. Alternatively, provide an existing `ORCID_PUBLIC_TOKEN` secret. Without these secrets, ORCID-linked **OpenAlex** discovery still works, but newly added ORCID works may take time to surface there.
- Optionally configure `OPENALEX_API_KEY` as a repository Actions secret for greater API limits. Keyless usage is supported for small requests.
- Newest six distinct public records go between the README's `AUTO-PUBLICATIONS` markers. The manually curated **Selected publications** section is never overwritten.
- If APIs fail or return no verified records, existing bibliography remains intact. New metadata can take time to appear in OpenAlex.

## GitHub statistics and private contributions

- GitHub GraphQL generates `assets/github-activity.svg` from the rolling-12-month contribution calendar, commit contributions, issues and PRs. Only aggregate values are shown, not repository identities or code.
- By default the workflow uses its own `GITHUB_TOKEN`, scoped to the profile repository. **Private contributions are NOT guaranteed** to be included with that token.
- On [your GitHub profile](https://github.com/AlessandroRongoni), choose **Contribution settings → Private contributions** to display anonymous contribution counts from private repositories to visitors.
- If the statistics generated by the workflow still omit private contributions, optionally supply a `PROFILE_STATS_TOKEN` secret with the minimum appropriate **read:user** permission, and where needed access to the relevant private resources. The token is used to query the GraphQL API, **never embedded in the README or SVG**. Grant only permissions you explicitly want to share, and avoid overly broad `repo` tokens where possible. Organization SSO policies can restrict access.
- GitHub only counts qualifying activities/commits associated with your identity; time spent coding, unpushed local work, and work outside GitHub are not measurable from this data.
- External `github-readme-stats` cards remain third-party widgets; their numbers and language metrics can differ and exclude private repos.

## Enable

1. Merge the proposed profile branch into `main` (scheduled workflows run only on the default branch).
2. Open **Actions → Sync research & GitHub metrics → Run workflow** to run the first sync.
3. Ensure Actions are enabled and can push updates (`contents: write` is set in the workflow). Some branch protections/rulesets may require adjustments.
4. Optionally add the repository Actions secrets above under **Settings → Secrets and variables → Actions**.
5. Inspect the Actions log for API errors. Automatic workflow commits only occur when content changes. GitHub may disable schedules on public repos after prolonged inactivity; this workflow normally writes only if new data is available.

No secrets are required for the basic OpenAlex lookup and public GitHub metrics.
