# Deploy the GitHub profile (V4)

This ZIP contains the **repository root contents**, NOT a directory to nest within your repository. The profile banner is a real PNG, `assets/profile-header.png` (the image you selected). `assets/ar-monogram.svg` remains available separately, but the header does not use the old SVG.

## Install using a feature branch

```bash
git clone https://github.com/AlessandroRongoni/AlessandroRongoni.git
cd AlessandroRongoni
git switch -c feat/profile-v4
unzip /path/to/AlessandroRongoni-github-profile-v4.zip -d .
git add -A
git commit -m "feat: restore full profile and refresh visuals"
git push -u origin feat/profile-v4
```

Open a Pull Request on GitHub from `feat/profile-v4` into `main`. Before merging, inspect **Files changed** and the rendered README, particularly if you have edited the repository since the earlier V3 package.

**Note:** the ZIP includes `.github/workflows/sync-research-profile.yml` (hidden folder). If the old repository still contains `assets/profile-header.svg`, it is unused but does not affect the new banner. To remove that old file in your PR, delete it explicitly: `git rm assets/profile-header.svg` (only if no other file depends on it).

## After merge

1. In your profile repository, go to **Actions → Update profile data → Run workflow** (on `main`).
2. Check the workflow summary for successful publications and GitHub metrics generation.
3. The **three classic visible GitHub stat cards** and the technology badges render from external services. The separate charts in **📊 More GitHub activity** are self-hosted assets generated by the workflow.
4. GitHub repository Settings → Actions → General must allow workflow write permission; branch protection/rulesets can prevent automated pushes.
5. The workflow runs each day at **03:17 UTC (12:17 JST)**, subject to GitHub scheduler delays.

## Advanced configuration

Open `AUTOMATION.md` for optional ORCID, OpenAlex and private-contribution token details.
